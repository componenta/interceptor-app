# Componenta Interceptor App

Interceptor App 4 предоставляет провайдер для приложений, переходящих на Interceptor 4, Config 4 и PHP 8.5.13+. Обработка атрибутов PHP принадлежит `componenta/interceptor`. Отдельной фазы сборки в этом пакете больше нет.

## Подключение

Зарегистрируйте `Componenta\Interceptor\ConfigProvider`. Он предоставляет перехватчик атрибутов, фабрику контекста вызова и фабрику цепочки HTTP-перехватчиков. Список `Componenta\Interceptor\ConfigKey::HTTP_INTERCEPTORS` задаётся в конфигурации приложения.

Существующие приложения могут продолжать регистрировать `Componenta\Interceptor\App\ConfigProvider`. Этот провайдер не добавляет фабрики или участников сборки. Его запись в метаданных Composer сохраняется для списка провайдеров на время перехода. Новые приложения могут обходиться без `componenta/interceptor-app`.

Interceptor 4 кеширует описания атрибутов PHP во время работы приложения. Атрибуты и аргументы их конструкторов создаются только при достижении соответствующего участка цепочки. Каждый вызов получает свежие экземпляры атрибутов; время жизни перехватчиков, получаемых как сервисы, определяют настроенные фабрики и контейнер. Методы с неполной классификацией атрибутов проверяются повторно, если позднее подключённый автозагрузчик делает класс атрибута доступным. Для этого не нужны обход классов приложения или артефакт метаданных.

## Переход с Interceptor App 3

Удалите регистрации и прямые обращения к следующим элементам:

- `Build\InterceptorBuilder` и `Build\InterceptorBuilderFactory`.
- `Factory\AttributeInterceptorFactory` из этого пакета. Используйте фабрику, предоставляемую основным провайдером Interceptor.
- `ConfigKey::MAP_FILE`, `ConfigKey::DEFAULT_MAP_FILE` и `interceptors.map_file`.

Старые файлы `interceptors.php` не используются. Их можно удалить при развёртывании: новый провайдер не читает, не перезаписывает и не удаляет их. Команда `app:build` не создаёт артефакт перехватчиков. `app:clean` снимает публикацию в общем хранилище сборки; отдельная очистка Interceptor не требуется.

Также удалены прежние `InterceptorMapCompiler`, `InterceptorMapContributor` и API регистрации участников компиляции. Позиции атрибутов не являются публичным контрактом подготовки Interceptor 4.

## Проверка

```bash
composer test
composer --working-dir=integration install
composer --working-dir=integration test
```

Тесты пакета используют настоящие провайдеры Config 4, DI 6 и Interceptor 4. Они проверяют свежие экземпляры атрибутов, позднее подключение автозагрузчика, игнорирование старых карт и сборку приложения без поиска перехватчиков.

Дополнительный интеграционный набор проверяет Symfony Serializer, PSR-7-ответы и пагинацию. Рабочие копии соседних пакетов должны соответствовать целевым версиям в `integration/composer.json`; сама таблица версий не означает, что соответствующие выпуски уже опубликованы.
